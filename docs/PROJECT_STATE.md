## 1) ما هو المشروع

تطبيق **دردشة فوري** (Instant Chat) — Next.js 16 (App Router) + TypeScript + Socket.IO مدمج في خادم Next مخصص (`server.ts`) + Prisma/SQLite + Tailwind/shadcn/ui.

- **تسجيل الدخول برمز OTP ثنائي القناة**: تيليغرام (البوت `@instant_chat_otp_bot`) أو رسالة SMS حقيقية عبر بوابة relay على هاتف أندرويد للمالك (أو Twilio/Vonage/HTTP إن أُضيفت لاحقاً).
- **واجهات متعددة**: تطبيق ويب كامل (PWA قابل للتثبيت) + نسخة خفيفة `public/legacy.html` لأقدم المتصفحات (REST فقط بلا WebSocket) + تطبيق أندرويد `android/InstantChat.apk` (Cordova بواجهة إطلاق ES5 تفتح النسخة الخفيفة).

## 3) آخر ما أُنجز (v2.4 — «بدي حقيقي مش تجريبي»)

**جعل تسليم رمز الدخول حقيقياً بلا متغيرات بيئة ولا إعادة نشر:**

1. **بطاقة «تفعيل الدخول الحقيقي (للمالك)»** في شاشة الدخول — تظهر فقط على خادم غير مهيأ. المالك يفتحها، يلصق توكن بوت تيليغرام، والتطبيق يتحقق منه فعلياً عبر `getMe` ثم يحفظه في قاعدة البيانات ويبدأ بولينج البوت **فوراً بلا إعادة نشر**.
2. **تخزين الإعدادات في قاعدة البيانات**: نموذج `Setting` (key/value) في Prisma + مكتبة `src/lib/settings.ts` بذاكرة مؤقتة (TTL 30 ث). **الأسبقية: متغيرات البيئة > قاعدة البيانات** — الطريقتان تعملان معاً.
3. **بوابة SMS relay مفعّلة**: بعد التفعيل يتولّد رمز بوابة ويرجع للتطبيق **أمر Termux كامل جاهز للنسخ** — يُشغَّل على هاتف أندرويد المالك (سكربت `public/relay-sms.sh`) ليُرسل SMS الحقيقية من شريحته.
4. **حماية**: قائمة بوتات مسموحة + حد 10 محاولات تفعيل/ساعة/عنوان IP.
5. قبلها (v2.3): خيار SMS ظاهر دائماً مع تبديل فوري بين القنوات، وendpoint `/api/auth/channels` يكشف القنوات للواجهة.
6. قبلها: إصلاح جذري لـ APK الهواتف القديمة (سامسونغ J5): شهادة توقيع جديدة صالحة 2024→2050 + واجهة إطلاق ES5 تفتح `/legacy.html`.

## 4) ما تبقّى بيد المالك (خطوات عند العودة — دقائق)

1. **تأكد أن Render نشر آخر commit** (`a51dd3a` أو أحدث — الشارة v2.4 تظهر في شاشة الدخول). إن لم يكن: لوحة Render → Manual Deploy.
2. **افتح التطبيق → بطاقة «تفعيل الدخول الحقيقي»** → الصق توكن البوت (من BotFather في تيليغرام) → «تفعيل». سيظهر أمر Termux — انسخه.
3. **شغّل أمر Termux على هاتف أندرويد** (ثبّت Termux من F-Droid) — سيسحب أوامر إرسال SMS من الخادم ويرسلها من شريحتك. هذه هي قناة SMS الحقيقية.
4. ملاحظة: إن كان قرص Render مؤقتاً (free tier) فالتهيئة والبيانات تُمحى عند إعادة النشر — أعد التفعيل من البطاقة (30 ثانية).
5. APK: ثبّت `android/InstantChat.apk` الجديد (إن رُكّب القديم وفشل: احذفه أولاً). يفتح النسخة الخفيفة على أي أندرويد ≥ 4.4.

## 5) نقاط معمارية يجب ألا تُنسى

- **Socket.IO مدمج داخل خادم Next** عبر `server.ts` مخصص — منفذ واحد للجميع (محلي/Render/APK القديم على `/socket.io`). لا تعد لفصل الخدمات.
- **`src/lib/settings.ts`**: كل الإعدادات (توكن البوت، رمز بوابة SMS، اسم المستخدم للبوت) تُقرأ: بيئة أولاً ثم قاعدة البيانات `Setting`. أي refactor جديد يتبع النمط نفسه.
- **`POST /api/setup`**: تحقق `getMe` + قائمة بوتات مسموحة (`SETUP_EXTRA_BOTS` للتوسيع) + حد محاولات + حفظ + بدء بولينج فوري. `GET /api/setup` حالة التهيئة بلا أسرار.
- **`/api/auth/channels`** يعيد `{telegram: boolean, sms: 'relay'|'twilio'|'vonage'|'http'|'demo'|null}` — الواجهة تعتمد عليه لعرض الأزرار. `'demo'` فقط خارج الإنتاج أو مع `OTP_DEMO_MODE=1`.
- **الكولداون لكل قناة على حدة** في `request-otp` (حقل `channel` ضمن شرط findFirst).
- **ترويسات no-store** على الصفحة والmanifest وواجهات API — لمنع مشكلة «النسخة القديمة في المعاينة» (كانت كارثية سابقاً).
- **شارة الإصدار** في `src/lib/version.ts` (`APP_VERSION`) تظهر بشاشة الدخول والشريط العلوي — **أي تعديل ظاهر = رفع الإصدار** (التالية v2.5).
- **بناء الـ APK**: سكربت البناء `build.py` + واجهة الإطلاق + مفتاح التوقيع خارج الريبو (في بيئة التطوير، مجلد `.apk-signing/`). نفس المفتاح = تحديث بلا إلغاء تثبيت. إن فُقدت البيئة تُعاد خطوات whatsapp-relay/apk من السجل.
- **legacy.html** تحتاج خادماً (مسارات API نسبية) — لا تفتحها كملف مباشر.

## 6) قواعد العمل الدائمة (اتفقتُ عليها مع المالك)

1. **الرفع إلى GitHub فور كل إنجاز** («أريد الرفع دائماً كل لحظة بلحظتها») — لا تجميع مؤجل.
2. **«شوف شو الأنسب وعملو»** — اختيار الحل الأنسب وتنفيذه مباشرة دون سؤال.
3. كل مهمة تُوثّق في سجل التطوير (نسخته هنا `docs/DEVELOPMENT_LOG.md`) بصيغة: Task ID + ما تم + ملخص مرحلة.
4. لا توكنات ولا مفاتيح في الريبو إطلاقاً (تحقق سريع قبل كل رفع).

## 5+1) مشاكل معلقة خفيفة (غير عاجلة)

- مؤشر «غير متصل… جاري إعادة الاتصال» ظهر قديماً في المعاينة — لم يُشخّص جذرياً؛ إذا تكرر: افحص اتصال Socket.IO بعد دمج `server.ts`.
- إن ظهرت النسخة قديمة في المعاينة المحلية رغم الرفع: امسح كاش المتصفح (no-store مفعّلة لكن التطبيق PWA مثبّت قد يحتفظ بالنسخة حتى تحديث Service Worker).

## 7) كيف تستأنف التطوير (لأي جلسة جديدة)

1. اقرأ هذه الوثيقة ثم [`docs/DEVELOPMENT_LOG.md`](./DEVELOPMENT_LOG.md) (آخر 2–3 مهام تكفي عادة).
2. بيئة التطوير: مشروع Next.js 16 + Bun — شغّل خادم التطوير فقط عبر سكربت التهيئة المعتاد (لا `bun run build`). اقرأ `dev.log` عند الشك.
3. عدّل الكود → **ارفع الإصدار في `src/lib/version.ts`** → تحقق متصفحاً → commit بنسخة المزامنة → push إلى main.
4. وثّق المهمة في سجل التطوير وأعد نسخه إلى هذا الريبو (كما فعلت هذه الجلسة) ثم ارفع مرة أخيرة.

> **ملاحظة أمنية:** توكن بوت تيليغرام يُفعّل من داخل التطبيق (البطاقة) أو من متغيرات بيئة Render (`TELEGRAM_BOT_TOKEN` + `TELEGRAM_BOT_USERNAME=instant_chat_otp_bot` + اختيارياً `SMS_PROVIDER=relay`) — ولا يُكتب في أي ملف داخل الريبو.
